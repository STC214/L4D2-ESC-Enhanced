## 喷漆源码模块

Go 的同一包源码保留在同一目录，不为“目录少一点”破坏构建关系。按职责分文件：

- `settings.go`：程序本地配置、动画帧数设置、游戏目录保存与外部改动保护。
- `import_policy.go`：转换策略、进度读取、清单备份保留策略。
- `core.go`：槽位状态、导入、构建及游戏部署／回退事务。
- `batch.go`、`vpk_import.go`：目录批量导入及 VPK 资源提取。
- `animation_import.go`、`apng.go`、`apng_file.go`、`quality.go`：图片／动画读取、合成与压缩。
- `main_windows.go`、`theme_windows.go`、`folder_windows.go`：窗口、主题及目录选择器。
- `*_test.go`：对应功能的回归测试；自制素材与模拟游戏目录，不把用户画面纳入开发预览。

## 生成输出与本地数据

| 目录／文件 | 管理方式 |
|---|---|
| `dist/` | 构建、打包及发布输出，默认忽略新增文件；已有少量历史已跟踪文件保留，不把忽略规则误当自动取消跟踪 |
| `reports/` | 构建日志、测试证据、源码／EXE 基线和审查产物，默认不上传 |
| `extracted/` | 解包产生的本地工作输出，默认不上传 |
| `喷漆/`、根目录 `142884156_p01.png` | 本地用户输入，已明确排除；不移动、不读取其画面、不打包发布 |
| 任意位置的 `CSP_Spray_Data/` | 对应 EXE 的本地配置、素材与游戏恢复记录，默认不上传；升级时保留 |
| `.release-backups/` | 本地 EXE 回退副本，默认不上传；验证后只保留最新可用一份 |

生产目录是本机路径 `D:\tools\01_Game_tools\spray_importer_go`，不属于仓库源码树。构建输出、生产安装和 Git 提交是不同步骤；不要将生产数据复制进源码后提交。

## 这次整理做了什么

1. 将喷漆配置逻辑从动画导入策略中分离到 `settings.go`，便于单独检查保存、迁移与错误保护。
2. 将混合多代实现的长文档移入 `docs/archive/spray_importer/`，原地址保留为导航页，旧链接仍可使用。
3. 当前教程统一为 `docs/喷漆工具使用说明.md`；README、文档索引和发布 ZIP 的使用说明均指向或使用它。
4. 保留构建依赖、测试证据、原始基线和用户输入的位置；没有批量删除历史文件，也没有碰真实游戏素材。

目录整理以可逆、引用完整和构建可复现为先，不把“看起来没用”作为删除依据。
