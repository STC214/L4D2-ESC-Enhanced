# C 开发与验证

适用：当前 C 1.3.1。以下命令均在项目根目录执行，不在本文所在的 `docs/` 目录执行。

## 开发条件

- Python；整包/原生分析测试还使用本机已安装的 `capstone`、`unicorn`。部分历史贴图研究工具另依赖 Pillow，不等于所有工具只需要标准库。
- Windows x86 构建工具。当前 `tools/build_c_session_plugin.py` 固定使用 MSVC BuildTools **14.44.35207** 和 Windows SDK **10.0.26100.0**，不是通用自动发现脚本；其他环境应先检查脚本路径。
- 当前游戏/客户端/GameUI 二进制与配套加载器，精确身份通过哈希和 ABI 校验，不套用未知版本偏移。
- 必须保留 `originals/` 中的固定原件/阶段基线和 `assets/c_flashlight/` 的固定资源。**仅 clone 仓库不保证具备全部本地原件**；原始 VPK/DLL、解包和多数报告不提交 Git，不要把工坊最新版冒充相同哈希的旧基线。

## 当前构建入口

```text
python -X utf8 tools/build_c_session_plugin.py
python -X utf8 tools/build_c_mod.py --width 1280 --height 720
python -X utf8 tools/full_review.py
```

- `build_c_session_plugin.py` 编译 DLL，并运行原生状态、提交桥接、真实 DLL 接口和屏幕外窗口回调测试，不启动 L4D2。
- `build_c_mod.py` 是当前整包入口；早期 `build_mod.py` 与 `--legacy-session` 仅用于历史复现。
- `full_review.py` 要求两轮完整检查成功，源码在审查期间不变，VPK/DLL/ZIP 哈希一致。自动化通过不代替全部游戏内效果验收。
- 改分辨率可用 `--width/--height` 或 `--video "实际video.txt完整路径"` 重建；这是构建时配置，不是同一个 VPK 实时读取分辨率。

主要输出：

```text
dist/【00】C_ESC_LED_血条和速度_TUMTaRA.vpk
dist/c_session_helper/CSessionDefaults.dll
dist/C_session_release.zip
dist/SHA256SUMS.txt
```

ZIP 包含 VPK、DLL 与清单；`SHA256SUMS.txt` 是发布附件，不能把 ZIP 内 `manifest.json` 误说成附带的 SHA256SUMS 文件。

## 验证与证据

| 路径（本地生成） | 用途 |
|---|---|
| `reports/c_current_review/verification.json` | 两轮字面命令、输出、退出码、源码与成品哈希 |
| `reports/c_checkbox_bridge/verification.json` | 勾选版相对两档基线的单一 RES 差异、DLL、补丁重放和恢复副本 |
| `reports/c_checkbox_bridge/patch.zip`、`menu.patch` | 勾选界面与配套 DLL 的载荷/差异，不是跨版本通用偏移补丁 |
| `reports/c_session_plugin_build.json` | 编译器命令、原生测试输出、DLL 哈希与固定二进制身份 |
| `reports/c_session_deploy/transaction.json`、`verification.json` | 最近一次实际部署的前后哈希、备份和核验 |

这些不是随 GitHub ZIP 分发的文件。部分历史试验包、重复恢复副本和窗口测试临时目录已清理；历史文档列出的生成文件可能需要重跑对应工具才存在。不要删除 `originals/` 基线来清理空间，也不要把文件不存在直接解释成未曾执行过测试。

## 部署与回退

当前部署器固定本机游戏目录 `E:\SteamLibrary\steamapps\common\Left 4 Dead 2`，不是面向任意电脑的安装 EXE。手动 ZIP 安装见 [使用说明](C使用说明.md)。

```text
python -X utf8 tools/review_c_session_deployment.py --deploy
python -X utf8 tools/c_session_release.py verify-installed
python -X utf8 tools/c_session_release.py rollback-preview
python -X utf8 tools/c_session_release.py rollback-game
```

部署与实际回退均应先退出游戏；`verify-installed` 和 `rollback-preview` 只读核对。回退恢复**最近一次部署前**的成套文件，依赖对应备份，不一定等于上一公开 Release；本机清理策略保留最近三份部署事务。文件回退不撤销全部已经写入玩家配置的参数。

旧 `deploy_c_integrated.py` 是整合独立手电测试包时的三文件迁移工具，不用于当前菜单更新的常规回退。

## 发布

```text
python -X utf8 tools/publish_github_release.py check
```

发布器校验两轮审查、源码未漂移、版本、VPK/DLL/ZIP 哈希，再准备校验附件。网络发布、Git 提交/标签与上传属于独立操作，只有明确要求推送时才执行；不要为了验证文档重发或覆盖已有 Release。纯文档整理不需要重部署游戏文件。

源码或构建工具变化后应重新审查；README/文档的更名不代表成品功能变化。旧版记录中的 74/76/221/222 成员、光圈 179/53/150、首次 ESC 初始化和右下聊天框，均不可当作当前默认行为。
