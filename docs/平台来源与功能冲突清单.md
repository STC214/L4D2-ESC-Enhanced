# 平台来源、VPK 下载逻辑与功能冲突清单

> **版本快照与研究结论。** 下文“本轮/当前”指记录日期及所检查的包，功能归属建议不是本机现状或强制依赖；不保证工坊最新版和现有安装仍相同。C 不内置这些平台的小地图/导航，当前 C 的安装与功能以 [使用说明](C使用说明.md) 为准。

记录日期：2026-10-25。比较对象为 **Skeeto 2.2.3 ↔ L4D2Evolved 1.2.5**，以 **L4N 为基底**。
本轮只获取公开资料、缓存安装包和静态比较，没有运行包内 DLL/BAT/PS1、安装 Skeeto、升级 L4N 或修改游戏/C。
机器可读清单：[workshop-platforms.json](workshop-platforms.json)。

## 2. 可复用的 VPK 下载逻辑

### 2.1 工坊订阅路径

订阅对应条目 → 等 Steam/游戏完成工坊下载 → 退出游戏 → 在
`<游戏根目录>/left4dead2/addons/workshop/<ID>.vpk` 找到文件。
这三个外层包应先验证 ZIP 魔数，再**保留原件、另存 `.zip` 副本到暂存目录**检查。
订阅下载不等于已部署根目录平台，不能只把这些外层 ZIP 当普通资源 VPK 启用。
未来 EXE 不应为下载而自动启动游戏，也不应直接照页面说明盲目覆盖游戏根目录。

### 2.2 官方详情 API → 实际文件 URL

```text
POST https://api.steampowered.com/ISteamRemoteStorage/GetPublishedFileDetails/v1/
Content-Type: application/x-www-form-urlencoded

itemcount=3
publishedfileids[0]=3787239937
publishedfileids[1]=3558049615
publishedfileids[2]=3785109042
```

处理顺序：

1. 从指定页面提取数字 ID；核对返回 `publishedfileid`、`result=1`、`consumer_app_id=550`。
2. 保存 `title`、`description`、`hcontent_file`、`time_updated`、`file_size` 和 `file_url`。
3. **下载 URL 来自该次 API 响应，不是页面 URL，也不是拼接 ID 猜出 CDN 地址。**
4. 用 HTTPS 获取 `file_url`，记录最终 URL、状态和失败信息；当前三条直链见 JSON 中的 `snapshot_file_url`。
5. 核对长度、计算 SHA-256、按魔数识别格式、校验 ZIP CRC，列出成员后才选择安装路线。
6. 无公开 `file_url` 时走 Steam 客户端订阅或用户提供的离线包；不能把预览图片 URL 当安装包。
7. 工坊更新后重新获取元数据和文件；当前直链与哈希只是此版本快照，不作为永久下载地址。

本轮工具支持主机恰为 `cdn.steamusercontent.com` 且请求失败时，保留同一对象路径尝试
`steamuserimages-a.akamaihd.net`，并记录两次结果；这不是任意站点的通用改写规则。
本轮新下载 Skeeto、L4N 均经原始 CDN 成功，没有触发此备用路线。
Evolved 与已有研究包的内容 ID、长度和更新时间一致，因此复用原包，再核对长度和 CRC；没有重复下载。

## 3. L4N 作为基底的处理原则

- 保留现有 L4N 配置；不为接入另外两者重置着色器、内存、模型或按键设置。
- 仍核对安装版本、插件接口和现有加载路线；“不用过多设置”不代表可以忽略版本差异。
- 当前 Evolved 使用 `bin/neko/plugins/L4D2Evolved.dll` 和 `L4d2evomodel.dll`；沿用这条路线，不叠装其 `winmm.dll` 备用入口。
- Skeeto **2.x** 使用根目录 `skeeto.dll` 与 `bin/wininet.dll`。不要按旧 1.x 方法，把新 DLL 直接复制到 L4N 插件目录。
- Skeeto 包内 README 明确要求 1.x → 2.x 单独迁移；不能把“保持订阅自动更新”理解为所有旧布局均可直接覆盖。
- 更新 Evolved/L4N 时保留本项目 C 与 `CSessionDefaults.dll`，不把其他平台的文件当多余文件清理。

## 5. Skeeto ↔ Evolved 功能重叠/条件性冲突矩阵

**证据等级：**“观察”指包内说明、配置或已解析菜单明确有该功能；“推断”指同时启用后的干预风险；“待实测”不是已复现崩溃。
当前没有双平台同时运行的实测记录，因此不能写成“二者必然互斥”，也不能宣称全功能共存已验证。

| 编号 | 功能/控制对象 | Skeeto 证据 | Evolved 证据 | 冲突类型、判断及建议归属 |
|---|---|---|---|---|
| F01 | 静态/动态准星 | 作者说明；`skeeto_xhair_toggle`；动态散布与贴图准星 | `DynamicSpreadCircleEnabled`、静态物品准星设置 | **功能重复观察；双画面推断。** 每类准星只留一套；本项目仍保持 Evo 动态准星关闭，不改变 C 原准星策略 |
| F02 | 命中/击杀/爆头视觉反馈 | HitFeedback 文档、普感/特感 JSON 预设 | `HitIndicatorEnabled`、`KillIndicatorEnabled` | **功能重复观察。** 同事件可能双图标/粒子，选一个平台负责，不是 VPK 覆盖问题 |
| F03 | 命中/击杀音效 | 命中反馈、`skeeto_audio_hit_sfx_volume` | `HitSoundEnabled`、`KillSoundEnabled` 与 vrmod 音效 | **功能重复观察。** 双开可能重复播放、音量叠加，选一套声音；与 F02 的视觉开关分开处理 |

### 本项目 C 的额外关联（不冒充 Evo 功能冲突）

- Skeeto 自定义 ESC/主菜单启用后可能替代 C 的全屏 ESC/TUMTaRA 入口。起始保持其关闭；`skeeto_escmenu_native`、`skeeto_mainmenu_native` 是文档给出的原生入口。
- Skeeto 血条、速度 HUD 与 C 的血条/速度属于显示重复，按模块选一套；这不是 Evolved 同名资源覆盖。
- Skeeto 布偶隐藏、描边、聚光灯、配置覆盖可能改变 C 默认效果；先停用对应 Skeeto 模块，不改本项目按连接会话初始化逻辑。

### 暂未找到对应重复项的功能

Evolved 的多模型资源库、256 骨骼/实时解算、MMD 舞蹈；Skeeto 的生涯统计、背景引擎、定制 ESC 编辑器和本地服工具，
不能仅因为同为客户端平台就列为互斥。独有功能仍可能共享渲染/缓存接口，属于后续组合实测，不是已确认冲突。

## 6. 共存验收与未来 EXE 的选项模型

L4N 保持不变，先验证 Evo 单独运行，再验证 Skeeto 单独运行，最后两者都加载但 Skeeto 重叠模块关闭。
随后按 F01–F13 **每次只启用一类功能**，记录版本哈希、两边实际开关、复现步骤和结果；比较入图、换图、断线重连、ESC、Alt-Tab 和分辨率变化。

未来 EXE 应按功能建立归属，如 `crosshair_owner`、`hit_visual_owner`、`hit_sound_owner`、`navigation_owner`、
`third_person_aim_owner`、`cache_policy_owner`；值可为 none / Skeeto / Evolved / existing。
“两边都启用”应显示重复或待验证提示，而不是偷偷重置 L4N 或删除另一平台。
配置注释、作者默认值、用户当前配置和真实生效状态分开保存；菜单开关不明确时只记录待核对，不猜写 ini 键名。

**当前结论：无已发现的安装文件硬覆盖；存在上述功能重叠及条件性干预风险。实际共存稳定性尚待游戏内验收。**
