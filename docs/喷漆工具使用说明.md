# CSP 喷漆处理工具使用说明

适用于 **Spray Studio 1.10.0**，对应项目发布版本 **v1.12.0**。

本文是面向使用者的操作手册。历史实现、开发验证和旧版原型记录见 [喷漆导入工具开发与历史说明](喷漆导入工具.md)，不以旧版本参数替代本文。

## 一、工具能做什么

这个工具用于管理项目的 **40 个喷漆槽位**，主要支持：

- 导入单张图片到指定槽位。
- 整目录批量导入、排序、重新编号。
- 直接导入最多两个成品喷漆 VPK，自动提取其中的喷漆资源。
- 转换静态图片、GIF 和 APNG。
- 预览静态喷漆及动画喷漆。
- 构建游戏所需的资源包并部署。
- 一键恢复全部默认槽位。
- 回退最近一次游戏部署。

**要分清三个操作：**

| 操作 | 作用 | 是否立即改变游戏文件 |
|---|---|---|
| 导入 | 将素材处理并保存到工具的槽位中 | 否 |
| 构建 | 根据当前槽位生成部署包 | 否 |
| 部署 | 将构建好的资源写入游戏目录 | 是 |

所以，**导入成功不等于游戏里已经更新**，还需要构建和部署。

## 二、打开工具前的准备

### 1. 工具位置

本机生产版本：

```text
D:\tools\01_Game_tools\spray_importer_go\CSP_Spray_Manager.exe
```

直接双击运行即可，日常使用不需要安装 Python、Go 或额外图片转换程序。

其他用户从 [v1.12.0 发布页](https://github.com/STC214/L4D2-ESC-Enhanced/releases/tag/v1.12.0) 下载 `CSP_Spray_Manager_v1.10.0.zip`，解压到有写入权限的目录后运行 EXE。

### 2. 游戏前置条件

游戏需要先安装本项目配套的：

- 独立喷漆选择器；
- `CSPSelector.dll`；
- 配套的 L4N 环境；
- 基础喷漆资源，包括 `update` 目录下的素材。

**本工具负责替换已有选择器的喷漆资源，不是基础选择器的一键安装器。**

如果是首次安装，请使用 Release 中的 `CSP_Selector_Complete_v1.12.0.zip`，按照其中说明安装；L4N 环境仍需自行准备。已有自定义喷漆时，不要直接用基础素材包覆盖。

### 3. 保留工具数据目录

EXE 旁边的：

```text
CSP_Spray_Data
```

保存着槽位清单、处理后的素材、母版、构建包及恢复记录。

升级、移动工具时，建议把 **EXE 和整个数据目录一起保留或移动**。只复制 EXE 到另一个空目录，会使用另一套数据。

## 三、界面各部分怎么用

### 游戏安装目录

填写包含 `left4dead2.exe` 的游戏根目录，例如：

```text
E:\SteamLibrary\steamapps\common\Left 4 Dead 2
```

不是：

```text
……\left4dead2\addons
```

非默认安装位置，每次打开后都应重新核对。当前游戏路径不会跨启动保存。

### 左侧槽位列表

共有 **01～40**：

- **默认**：使用内置默认编号图。
- **已导入**：该槽位已有自定义喷漆。

成功导入后，工具中的显示名统一为：

```text
喷漆 01
喷漆 02
……
喷漆 40
```

工具管理的贴图副本也按槽位编号命名，例如：

```text
test_001.vtf
test_002.vtf
```

**不会把你准备的原始图片或原始 VPK 改名。**

### 中间预览区

点击槽位后显示对应喷漆：

- 静态喷漆显示静态预览；
- 保留下来的动画喷漆循环播放；
- 预览区域保持正方形；
- 图片按比例居中，空余部分显示预览背景，不强行拉伸或裁切。

这是缩放预览，**不是原始图片的逐像素、原尺寸展示**。

### 动画最低帧数

右上角可以输入 **2～256** 的整数，默认 **30**。

它表示：处理后至少能保留多少帧，才把素材作为动画喷漆导入。

开始导入时会校验并保存设置，下次打开继续使用。详细规则见第六节。

### 进度条

导入过程中会显示读取、校验、合成、压缩、保存等阶段。

进度按实际阶段和处理量更新，不是按时间自动增长。因此：

- 某些阶段暂时停在同一百分比属于正常现象；
- GIF 解码时尤其可能停留一段时间；
- 目录导入会汇总各个素材的处理进度。

处理期间相关操作会暂时禁用，请等待完成或明确报错。

## 四、八个按钮的用途

| 按钮 | 用途 |
|---|---|
| 导入 VPK（最多2个）… | 提取一个或两个喷漆 VPK 中的素材 |
| 整目录导入并排序… | 导入目录及子目录中的支持格式，并统一排序 |
| 单张导入到当前槽位… | 替换左侧当前选中的槽位 |
| 构建部署包 | 根据当前全部槽位生成游戏资源 |
| 部署到游戏 | 退出游戏后，将最近构建写入游戏 |
| 回退最近部署 | 恢复最近一次部署前的游戏文件 |
| 打开数据目录 | 打开当前工具的数据文件夹 |
| 恢复全部默认槽位… | 清空全部自定义绑定，恢复默认槽位 |

## 五、三种导入方式

### 方式一：单张导入，适合替换指定编号

例如只想替换第 17 个槽位：

1. 点击左侧“喷漆 17”。
2. 点击“单张导入到当前槽位…”。
3. 选择图片或 VTF。
4. 等待进度完成。
5. 查看预览和处理结果。
6. 点击“构建部署包”。
7. 完全退出游戏。
8. 点击“部署到游戏”。

**单张导入只替换所选槽位，不会把其他槽位重新排序。**

### 方式二：整目录导入，适合批量整理

1. 将准备导入的素材放进一个目录。
2. 如果要替换整套素材，先点击“恢复全部默认槽位…”。
3. 点击“整目录导入并排序…”。
4. 在资源管理器式窗口中选择素材目录。
5. 等待全部处理完成。
6. 核对排序和预览。
7. 构建，退出游戏，再部署。

目录导入包括子目录，非支持格式会略过。

排序采用原文件名的自然排序，例如：

```text
1.png → 2.png → 10.png
```

而不是：

```text
1.png → 10.png → 2.png
```

注意：

- 目录素材会与已有素材合并，**不是自动替换整套**。
- 合并后会连续重新分配编号，已有喷漆的槽位可能变化。
- 重复导入同一路径的素材通常会更新原记录。
- 超过 40 个槽位会停止整批提交，不会偷偷只取前 40 个。
- 支持扩展名的文件如果损坏，也会停止整批提交。

### 方式三：直接导入成品喷漆 VPK

1. 点击“导入 VPK（最多2个）…”。
2. 选择一个 VPK；或在同一目录中按住 **Ctrl** 选择两个。
3. 确认导入提示。
4. 工具自动拆解、提取、排序和编号。
5. 完成后检查槽位。
6. 构建，退出游戏，再部署。

工具不是把整个 VPK 原样安装，而是提取喷漆贴图，生成当前选择器所需的编号资源。

需要注意：

- 两个包里的同名喷漆资源会分别保留。
- 原始 VPK 不修改。
- 导入结果与已有素材合并，总数仍须不超过 40。
- 重复导入同一路径包中的同一资源会更新。
- 包里后来删除的资源，不会自动从已有槽位中清除；要整套换新，先恢复默认。
- 支持单文件 VPK v1/v2；依赖外部分卷的包不支持。
- 每包上限为 256 MiB，包内结构、引用和 CRC 都需要通过检查。

## 六、动画最低帧数：最重要的设置

### 判断的是“处理后可保留帧数”

不是原图有 100 帧，设置为 30 就一定能保留动画。

工具先根据当前清晰度和体积预算，计算能保留的连续前缀帧数，再与阈值比较：

```text
可保留帧数 < 阈值 → 只取第一帧，生成静态喷漆
可保留帧数 ≥ 阈值 → 保留动画
```

### 当前版本的实际情况

当前转换策略为：

- 动画游戏贴图：**512×512 DXT1**；
- 容量限制内：**最多连续前 3 帧**；
- 不通过大幅降低分辨率来凑帧数。

因此：

| 原素材 | 预算可保留 | 最低帧数设置 | 导入结果 |
|---|---:|---:|---|
| 多帧 GIF/APNG | 3 | 30，默认 | 首帧静态 |
| 多帧 GIF/APNG | 3 | 4 | 首帧静态 |
| 多帧 GIF/APNG | 3 | 3 | 保留前 3 帧动画 |
| 两帧 GIF/APNG | 2 | 2 | 保留两帧动画 |
| 两帧 GIF/APNG | 2 | 3 | 首帧静态 |

**希望保留当前版本的 GIF/APNG 动画，请在导入前设为 2 或 3。**

修改这个设置不会追溯改变已经导入的素材。需要重新导入原始动图，再构建部署。

### 转为静态时，取哪一帧？

取动画**正确合成后的第一帧**，不是任意截取，也不会把 APNG 的隐藏默认图误当动画第一帧。

原始动图保持不变。

### VTF/VPK 中的现成动画

上述阈值用于 GIF/APNG 等图片转换。

现成动画 VTF，包括从 VPK 提取的 VTF，符合格式及体积要求时会按原字节保留，**不受这个阈值影响**。

### 播放节奏

GIF/APNG 转换后的动画使用统一帧率循环播放，不完整保留原动图的不等长帧延时或有限循环次数。因此，保留动画也不等于完整复现原动图。

## 七、分辨率和画质

### 普通静态图片、动图首帧静态回退

- 保存 **1024×1024 母版**；
- 游戏贴图为 **1020×1024 DXT1**；
- 成品贴图大小为 **522320 字节**。

实际游戏贴图不是严格的 1024×1024，是为了给文件头留出空间，满足小于 512 KiB 的限制。

### 保留下来的 GIF/APNG 动画

- 每个保留帧保存 1024×1024 母版；
- 游戏动画贴图为 512×512 DXT1；
- 最多保留连续前 3 帧；
- 三帧贴图大小为 393296 字节。

### 现成 VTF/VPK

按原字节保留：

- 不自动放大；
- 不重新压缩；
- 不用 1024 母版重新加工。

### 是否原画质？

**转换后的游戏贴图不是无损原画质。**

DXT1 是有损压缩，而且只有 1 位透明度：

- alpha 小于 128：透明；
- 其余：不透明。

半透明边缘、阴影或渐变可能出现量化。PNG 母版保留更完整的透明度，但母版不会作为大图直接部署进游戏。

小尺寸原图即使放大到 1024，也不会凭空增加细节。旧版已生成的低清贴图，需要重新导入原图；仅重新构建不会恢复细节。

## 八、支持哪些格式

| 格式 | 当前支持情况 |
|---|---|
| PNG | 静态图片 |
| APNG | 支持动画，包含扩展名为 `.png` 的 APNG |
| JPG/JPEG | 静态图片 |
| GIF | 静态或动画 |
| BMP | 未压缩 24 位 BMP |
| VTF | 支持范围内的静态、动画二维贴图 |
| VPK | 最多两个完整单文件喷漆包 |
| WebP、TGA | 当前原生版不支持，先转换为支持格式 |

主要边界：

- 普通静态图片输入上限为 32 MiB。
- 动画 APNG 单独走流式处理，输入上限为 1 GiB，但仍受画布、块数和保留数据预算限制。
- GIF 输入上限为 32 MiB，最多 256 帧，并有像素预算限制。
- 原样 VTF 必须**小于 512 KiB**，支持 1～256 帧。
- VTF 支持 7.0～7.5 的二维贴图及 RGBA/BGRA/RGB/BGR/DXT1/DXT3/DXT5 等既定编码。
- 文件较小也不代表一定能导入，结构损坏或编码超出支持范围仍会报错。
- JPEG 不自动按 EXIF 方向旋转，导入前应先把正确方向实际保存好。

## 九、怎样换一整套喷漆

使用这个顺序：

```text
恢复全部默认槽位
        ↓
导入新的图片目录或 VPK
        ↓
检查编号、静态/动画结果和预览
        ↓
构建部署包
        ↓
完全退出游戏
        ↓
部署到游戏
```

“恢复全部默认槽位”会清空当前自定义绑定，但：

- 不删除原图；
- 不删除历史素材和母版；
- 不直接修改游戏文件；
- 不是释放全部缓存空间的按钮。

如果只想让游戏恢复内置默认图：

```text
恢复全部默认槽位 → 构建 → 退出游戏 → 部署
```

## 十、部署后怎样在游戏里选择

1. 部署完成后重新启动游戏。
2. 进入配套选择器入口，通常是：**选项 → 多人游戏 → CSP TEST**。
3. 点击喷漆图片或编号。
4. 在确认区域确认应用。
5. 再进入战役。

**应当在进入战役前选择。** 局内重新选择不会立即刷新实际喷绘。

工具预览和游戏内选择区都支持保留下来的动画，但具体游戏渲染效果仍需在实际环境中检查。

## 十一、备份和回退分别是什么意思

### 清单备份

只保留最新一套：

```text
before.json
after.json
```

分别记录该次操作前后的槽位清单。

这不代表所有历史图片、母版和构建包都被删除，所以数据目录仍可能继续增长。没有有效替代备份、存在待恢复事务或清理失败时，会保留旧记录；不要为追求数量手动删除恢复文件。

### EXE 备份

生产维护流程只保留最新一份可用的旧 EXE，用于回退工具版本。

**它不是游戏喷漆的恢复按钮。**

### 游戏部署备份

游戏部署恢复记录另行保存，不属于清理旧清单、旧 EXE 的范围。

点击“回退最近部署”会恢复最近一次部署前的游戏文件，但不会：

- 清空当前导入清单；
- 把全部槽位恢复默认；
- 卸载基础选择器。

发现文件被外部修改或存在未完成事务时，工具会停止相关操作，请保留数据和恢复记录。

## 十二、常见问题

### 导入成功，但游戏还是旧图

检查是否完成：

```text
导入 → 重新构建 → 退出游戏 → 部署 → 重启游戏
```

只导入或只构建，都不会改变游戏文件。

### 导入动图，结果却是静态

先看最低帧数设置。默认 30，而当前高清转换预算最多 3 帧，因此会按规则取首帧。

希望保留动画，设为 2 或 3 后重新导入原动图。

### 修改阈值后，旧素材没有变化

设置只影响后续导入。重新导入原素材，再构建部署。

### 提示超过 40 个槽位

目录和 VPK 导入会与已有素材合并。若准备整套换新，先恢复全部默认槽位。

### 提示“请重新构建”

构建后又修改过槽位。重新构建即可，不要使用旧构建部署。

### 提示只能导入小于 32 MiB 的素材

先确认素材格式：

- 普通静态图片和 GIF 仍有 32 MiB 限制；
- APNG 使用独立流式路径。

若确认是 APNG，请保留原文件和报错日志，并核对工具版本。

### 预览看起来不够清晰

预览是缩放显示，不等于实际游戏贴图分辨率。还应检查输入本身是否低清、是否使用了旧版生成的素材，以及导入结果中的实际输出尺寸。

### 清理后数据目录仍然很大

当前只清理已被替代的清单快照和 EXE 备份，不会顺便删除历史素材、母版、构建包或游戏恢复记录。

不要直接删除正在使用的数据目录。

### 出错后需要提供什么？

建议提供：

1. 工具版本；
2. 使用的导入方式；
3. 素材格式、大小；
4. 动画最低帧数设置；
5. 报错完整文字；
6. 数据目录中的：

```text
logs\last-error.json
```

需要更多过程记录时，再提供：

```text
logs\errors.jsonl
```

这些诊断日志记录错误文本，不保存喷漆图片内容。
