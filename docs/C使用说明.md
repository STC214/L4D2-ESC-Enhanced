# C 使用说明（1.3.1）

> 1.3.1 修复旧勾选框缺少提交的问题，并支持“地图全亮”等参数的延迟确认；必须同时更新 VPK 与 DLL，见 [勾选与提交说明](C勾选与提交.md)。旧版 Release 附件保留，不应与本版混装。

适用于 `【00】C_ESC_LED_血条和速度_TUMTaRA.vpk` 和配套 `CSessionDefaults.dll` **1.3.1**。

## 一、下载哪个文件

进入 [v1.3.1 发布页](https://github.com/STC214/L4D2-ESC-Enhanced/releases/tag/v1.3.1)，下载 **`C_session_release.zip`**。

| 发布文件 | 用途 |
|---|---|
| `C_session_release.zip` | 推荐下载：包含菜单 VPK 和自动默认项 DLL，按游戏目录结构打包 |
| `C_ESC_LED_Health_Speed_TUMTaRA.vpk` | 单独的菜单/HUD 包，不含自动默认项 DLL；安装时使用下文固定中文文件名 |
| `SHA256SUMS.txt` | 用于核对下载文件是否完整 |

**首次安装和升级均推荐使用 ZIP，不要只替换 VPK。** 本版包含勾选提交所需的 DLL；手电资源和轮廓初始化功能继续保留。

## 二、安装前准备

1. 完全退出求生之路 2。
2. 确认游戏根目录：即包含 `left4dead2.exe`、`bin`、`left4dead2` 的目录，而不是里面的 `left4dead2` 子文件夹。
3. 本机示例路径为 `E:\SteamLibrary\steamapps\common\Left 4 Dead 2`；其他电脑使用自己的 Steam 安装位置。
4. 自动默认项需要现有 **L4N 插件加载器**。基底来源为 [NekoShaders & L4N](https://steamcommunity.com/sharedfiles/filedetails/?id=3558049615)，按作者说明准备基底；C 的 ZIP 不包含完整基底平台。
5. 备份现有同名 VPK 和 `bin/neko/plugins/CSessionDefaults.dll`；备份放在游戏加载目录之外。

如果原有 L4N 已正常工作，保留其设置，不要为了安装 C 顺带替换其他平台文件。Evolved、Skeeto 不是 C 这套默认项功能的必需组件，小地图和导航也不是 C 自身提供的功能。

## 三、安装或升级

将 ZIP 解压到**游戏根目录**，确认形成以下结构：

```text
Left 4 Dead 2/
├─ left4dead2.exe
├─ left4dead2/
│  └─ addons/
│     └─ 【00】C_ESC_LED_血条和速度_TUMTaRA.vpk
└─ bin/
   └─ neko/
      └─ plugins/
         └─ CSessionDefaults.dll
```

- 覆盖的是本套 C 的同名文件，不要覆盖无关模组或平台配置。
- 若解压软件生成了额外的 `C_session_release` 外层文件夹，将里面的 `bin` 和 `left4dead2` 合并到游戏根目录。
- ZIP 内 VPK 已保留固定中文文件名，不需要改名。单独下载英文名 VPK 时，重命名为上图文件名。
- 游戏“附加内容”中保留 C，停用旧版 C、原版 A/B，以及覆盖同一 ESC 菜单或 HUD 资源的模组。工坊订阅的旧副本也可能重新下载，请检查重复启用情况。
- 不要把原版和成品、历史包、备份包一起放入 `addons`。
- 之前参加手电测试的用户，将 `C_flashlight_nofade_TEST.vpk` 移出加载目录；对应着色器已经集成到 C。不要同时加载其他覆盖 `flashlight_ps30.vcs` 或手电贴图的包。

## 四、进入游戏后怎么用

1. 重新启动游戏并进入可游玩的地图，默认项会自动初始化，**不需要按 ESC，也不需要输入命令**。
2. 按 **ESC** 打开全屏选项菜单。背景采用整屏约 **91% 不透明**黑色填充，游戏画面仅隐约透出。
3. 使用菜单开关或滑条调整设置；10 个真正二值项目使用原生勾选框，连续数值仍用滑条。修改后反复开关 ESC 不会重置。
   二值项集中排在前面，勾选/取消即提交；“地图全亮”可能到后续渲染帧才应用，组件会延迟确认，不会因为第一次读回旧值就立即反转勾选。
4. 下一关、同图重载或重新连接房间/服务器后，天气、尸体和手电默认项重新初始化一次。

### 当前默认项

| 设置 | 默认值 | 说明 |
|---|---:|---|
| 雨量 | 0 | 最低值 |
| 雪量 | 0 | 最低值 |
| 迷雾／雾覆盖 | 0 | `fog_override` |
| 雾气开启 | 0 | `fog_enable` |
| 尸体数量 | 0 | 客户端 `cl_ragdoll_maxcount` |
| 关闭角色轮廓 | 0／不勾选 | `sv_disable_glow_survivors`，即不禁用轮廓 |
| 关闭远处物品轮廓 | 0／不勾选 | `sv_disable_glow_faritems`，即不禁用远处物品轮廓 |
| 光亮度 | 1 | 当前菜单最大值 |
| 光射程 | 3000 | 当前菜单最大值 |
| 手电光圈 | **165** | `r_flashlightfov`，菜单范围 **50～200**，步进 1 |

这些值是初始化值，不是持续锁定。手电光圈不再使用“首次 ESC 设为 150”的旧逻辑，也不再以 53 作为连接默认值。

两个轮廓参数每次进图只尝试写入 0，不修改变量标志、不持续强制；它们是服务端复制变量，服务器可能覆盖。0 表示不禁用对应轮廓，并非保证所有角色或物品在任何墙后都可见。服务端实体、地图特效及其他插件可能独立控制画面；客户端尸体数量 0 不代表删除服务端全部尸体实体。

### 开关文字与手电整合

勾选表示执行该项文字描述的效果：电视亮度模式、显示字幕、显示游戏提示、关闭角色轮廓、关闭远处物品轮廓、显示导演强度信息、地图全亮、导航网格编辑、覆盖地图雾参数、显示雾气。特别注意，两个“关闭轮廓”开关**不勾选才是不禁用轮廓**；不使用误导性的反向标签。服务器限制仍适用。

手电保留普通 DXT5 贴图格式，顶层 RGB 均值约 190.00；集成已测试的末端淡出抑制和着色器 RGB 2 倍计算。不增加纹理采样；RGB 计算倍率不等于实机观感必然翻倍，也不代表消除全部距离、角度、材质或阴影造成的明暗变化。

### HUD 与 TUMTaRA

- 集成血条、速度数字和速度仪表盘；未引入血条/速度来源模组的准星功能。
- 速度表保持来源默认位置。聊天区域位于速度图形表与右侧武器 HUD 之间，输入框底边对齐本玩家血条底边。
- 游戏主菜单提供 **TUMTaRA** 入口。菜单入口不等于地图本体；训练地图需另外安装 [TUMTaRA 地图包](https://steamcommunity.com/sharedfiles/filedetails/?id=469986973)，菜单中的其他可选地图也有各自依赖。
- 不同画面比例、字体和 HUD 模组仍可能影响实际排版，需在自己的游戏中检查。

### 网络图与分辨率

发布包使用 **1280×720** 配置，网络图位于右上方，高度值为 620。该高度是从窗口底部计算的像素值，**不要把它当作所有分辨率都适用的自动适配值**。

更换分辨率后，如果网络图越界，在 ESC 的网络图高度选项中调低至可见范围；拥有源码环境时，也可按实际分辨率重新构建。手动调整会保留在当前会话中，重新连接时会重新执行包内连接配置。

## 五、确认自动默认项是否生效

进入地图后，在游戏根目录查看 `CSessionDefaults.log`。检查**本次启动对应的最新记录**，不要把旧会话中的 `FIRST_ESC` 日志当作新版行为。

```text
DEFAULT_VERIFIED: r_flashlightfov requested=165 actual=165; flags unchanged
DEFAULT_VERIFIED: r_flashlightconstant requested=1 actual=1; flags unchanged
DEFAULT_VERIFIED: r_flashlightfar requested=3000 actual=3000; flags unchanged
```

天气和尸体项应有对应的 `requested=0 actual=0`。`READY` 只表示定时器已创建，`TIMER_ACTIVE` 表示回调已经触发，实际变量结果以 `DEFAULT_VERIFIED` 读回为准。

建议检查：进图为 165 → 手动改成 80 → 反复 ESC 仍为 80 → 下一关或同图重载恢复 165。游戏主菜单、加载画面和录像播放不应触发可游玩地图初始化。

## 六、常见问题

| 现象 | 优先检查 |
|---|---|
| 菜单正常，默认项没生效 | DLL 是否放对路径、L4N 是否已正常安装并加载、是否重启游戏 |
| 还是首次 ESC 变成 150 | 是否仍加载旧 DLL；同时检查重复 C 和旧会话日志 |
| 没有新增日志 | 检查加载器及 DLL 路径；确认查看的是实际游戏根目录 |
| 出现 `DEFAULTS_DISABLED` 或 `DISABLED` | 查看本条具体原因；游戏更新可能使组件的版本/接口校验不匹配，不要移除校验强行使用 |
| 雨雪或尸体仍可见 | 核对本次变量读回，再检查是否为地图独立特效、其他模组或服务端控制的对象 |
| TUMTaRA 菜单打开但地图启动失败 | 检查训练地图本体和对应可选地图是否安装 |
| 聊天或速度表重叠 | 检查覆盖同名 HUD 资源的其他模组，并记录分辨率及截图 |

组件针对已检查的 Windows x86 游戏版本。游戏、L4N 或其他平台升级后需重新确认兼容性；C 不会自动下载或适配未知游戏版本。

## 七、卸载与回退

完全退出游戏后，将本套 C 的 VPK 和 `CSessionDefaults.dll` 移出各自加载目录；需要回退时恢复自己备份的**成套 VPK 与 DLL**。不要删除整个 `addons`、`plugins`、L4N 或其他平台目录。

卸载会停止后续自动初始化，但不会自动撤销已写入游戏配置的所有变量。需要恢复某个游戏原生值时，应单独核对该变量，不要把 C 的自定义默认值当作原生默认值。

由本项目部署脚本安装、且本机保留事务记录和备份的情况下，可在项目目录执行：

```text
python -X utf8 tools/c_session_release.py rollback-preview
python -X utf8 tools/c_session_release.py rollback-game
```

以上恢复最近一次成套部署前的 C 与 DLL，预览不写入游戏；不会重新启用旧独立手电测试包。旧三文件整合事务属于历史记录，不用于回退当前菜单更新。从 GitHub 只下载 ZIP 的用户请使用自己的手动备份。
