## 结论

**当前证据未显示必须修改 Evolved 的 DLL；主要需要调整安装路线和 Evolved 的配置。优先沿用现有 L4N 插件加载，不整包盲目覆盖。**

这是一份待游戏验证的适配方案，不是已经证明全部兼容的安装结果。

## 需要做的 Evolved 侧适配

### 1. 采用现有 L4N 加载：不先叠加第二套加载器

拟安装：

```text
bin/neko/plugins/L4D2Evolved.dll
bin/neko/plugins/L4d2evomodel.dll
```

两者必须配套，不单独只放核心 DLL。保留现有游戏 EXE、`bin/left4neko.dll`、L4N 配置及插件头文件。

**在这条方案中，首轮不安装原包的根目录 `winmm.dll` 和 `bin/winmm.dll`。** 原因不是已有同名文件冲突——实际两条目标路径目前都不存在——而是已有 L4N 插件加载入口，不先引入额外代理加载路径，便于排查重复初始化和加载顺序问题。

作者页面列出可使用 L4N 的路线；本机头文件和插件导出表提供了静态对应证据。仍需首次启动后检查 L4N 插件列表/日志和 F8，才算验证加载成功。若失败，先查看依赖与日志，不立刻改游戏 EXE或加入第二套加载器。

### 2. 保留现有 DXVK，先禁用 Evolved 的帧生成与自动 DXVK 安装

建议在将来生成的 `游戏根目录/Evolved/config.txt` 或 F8 中明确设置：

```ini
FrameGenerationEnabled=false
InstallBundledDxvkIfMissing=false
```

包内 `Evolved/d3d9.dll` 可按原目录保留为备用组件，不把它挪到根目录或 bin 下替换现有 DXVK。也不因发现该文件就认定已经生效。

当前 MSAA、垂直同步、L4N `lock_datacache_size=1` 等设置先保持原值。作者说明检测到 L4N 时采用其缓存策略，没有证据需要先改 L4N 缓存参数。帧生成不是基础安装必需项，应在基础功能稳定后单独测试。

### 3. 避开当前游戏的 F5 / P 按键

建议改 Evolved 的键，不改玩家原有绑定：

```ini
NoHmdConfigMenuKey=key:f8
ModManagerMenuKey=key:f9
ClientDancePlaylistKey=key:f10
```

这样 F5 继续截图、P 继续执行 `SM_LDW`。F4/F6/F7 保留 Evolved 默认键；反斜杠继续打开 L4N 菜单。F9/F10 只是基于当前游戏配置未绑定作出的候选，首次启动需确认输入系统是否拦截。

配置样例中的 `#` 表示这些项是注释参考，不能直接原样复制后宣称生效。以上是拟议配置片段，尚未写入游戏。建议先让 Evolved 生成真实配置，退出游戏并备份，再在 F8 或真实配置中局部调整；不要把 `config.sample` 整体覆盖成玩家设置。

### 4. 保留 C 的准星方案，避免先叠加动态准星

建议首轮明确设置：

```ini
DynamicSpreadCircleEnabled=false
```

该键只对应动态散布圈，不等于已经关闭 Evolved 的全部固定准星、命中或击杀指示。F8 中还应逐项确认相关视觉层是否与 C 叠加；没有证据支持的配置键不编造。C 的血条、速度仪表、LED 和 ESC 本轮不改。

ADS 激活键也先保持未分配，再在 F8 设置，避免一开始占用原有右键推击或中键缩放功能。角色/武器全部预加载、自动随机模型等非必要功能首轮不额外开启，减少排查变量。

### 5. 配套资源按原结构安装，保持游戏模组管理状态

拟安装的资源：

```text
left4dead2/addons/killicon.vpk
left4dead2/addons/mdR_Anims_Base_for_l4d2vr.vpk
left4dead2/sound/vrmod/headshot.wav
left4dead2/sound/vrmod/hit.wav
left4dead2/sound/vrmod/kill.wav
Evolved/config.sample
Evolved/version.txt
Evolved/d3d9.dll
manifest.json
updatelog.txt
```

这些具体目标文件本次均未发现已存在；安装前仍应重新检查，避免评估后状态变化。配套卸载 BAT 不是运行必需项，可只保留在项目作为参考，不执行。

之前对两个内置 VPK 的核对，仅与 C 有 `addoninfo.txt` 同名，没有同路径运行资源覆盖；**没有全量解析本机所有大型地图和工坊 VPK**，也没有证明原生 DLL 的运行时行为绝无冲突。

本机有大量大型地图包。首次进 F5 不执行批量启停、优先级重排或“应用并刷新”，先保存/备份既有模组启用状态，避免改变当前地图和 C 的加载组合。

### 6. 小地图采用单一实现

游戏当前插件目录没有安装项目中 `独立版map更新/` 的 `L4N_Minimap.dll`，本轮也未复制它。首轮可沿用 Evolved 的小地图默认方案；若之后使用独立小地图，再显式关闭 Evolved 的对应功能，避免双重绘制或快捷键冲突。

Ctrl+M 是 Evolved 样例中的切换组合；游戏 Ctrl 已是蹲下、M 已是选队，是否同时触发取决于插件的输入拦截。先用 F8 菜单确认或改键，不能仅凭组合键不同就认定无冲突。

## 无需预先做的修改

- 没有证据要求反编译或修改两个 DLL。
- 不替换现有 L4N、游戏 EXE、根目录/bin 下的 DXVK 或 `dxgi.dll`。
- 不必再次安装 L4N；已有本机安装与日志证据。
- 不把 Evolved 原生插件塞进 C 的 VPK。
- 首轮不添加 `-noevo`：该参数按作者包内日志会禁用 Evo 核心，不适合用来验证完整 F8/F5 功能。
- 没有检查 Steam 账户配置或实际启动快捷方式，不能声称已知当前 Steam 启动项。现有 BAT 文本为 `left4dead2.exe -steam -novid`，文件存在不等于用户实际通过它启动。

## 安装后的验收顺序（尚未执行）

1. 备份拟变动路径与玩家配置；确认游戏退出。
2. 仅按 L4N 路线加入两个插件与配套资源，不加两份 winmm 代理。
3. 正常启动，检查加载日志/插件菜单，按 F8。记录缺失依赖或初始化失败信息。
4. 调整上述按键，分别验证 F5 截图、P 原命令和 Evolved 新键。
5. 进入本地测试图，核对 C 的 ESC、网络图、血条、速度、准星和手电，再测 Evolved 身体/模型与小地图。
6. 最后才逐项测试 ADS、帧生成、批量模组管理等功能；不以成功进主菜单代替全部验证。

若回退，按实际安装清单恢复备份或移除本次新增文件；保留 L4N 原有文件和玩家配置。原包卸载脚本可删除数据目录，本轮没有执行它，也不把它作为无条件回滚方案。

## 另一个观察，不属于本次修改

本机 `addonlist.txt` 中看到旧 C 文件名的启用记录，而实际文件已是固定新名；这份列表不能独立证明当前新 C 已启用或停用。下次游戏内应确认附加内容中当前 C 的状态；本轮不修改该文件。项目成品与实际安装包的哈希一致性已确认。
